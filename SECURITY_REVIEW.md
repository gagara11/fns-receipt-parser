# Проверка безопасности

Дата исходного review: 2026-09-19; дополнение по наблюдаемости: 2026-09-26. Основа: `TumanovNV/fns-receipt-parser`,
commit `76789118d10239954f2317a365784f9164d5f8a3` (MIT).
Это прикладной review кода и тесты, не независимый пентест и не гарантия отсутствия уязвимостей.

## Исходный код

В рассмотренном Python CLI не обнаружены сторонние адреса для отправки чеков/токенов,
исполнение загруженного кода, shell-команды или обфускация. API-host зафиксирован на ФНС;
исходный CLI использует стандартную библиотеку. Лицензия и оригинальный CLI сохранены.

Исправления в fork:

- Стандартное следование HTTP-редиректам могло унести Authorization на другой host.
  Все редиректы запрещены, системные HTTP proxy переменные не используются; TLS проверяется.
- Чтение ответов без ограничения могло исчерпать память. Установлен предел 8 MiB.
- Недоверенные строки товаров/продавцов могли интерпретироваться как CSV-формулы.
  Опасные текстовые префиксы экранируются; числовые поля не меняются.
- Для сервера добавлены обязательный Bearer, Host/Origin-проверки и лимит запроса 64 KiB.
- SQL-фильтры параметризованы, лимиты страниц проверяются; MCP не принимает URL, shell
  команды, пути файлов и не имеет инструмента чтения/изменения секретов.
- Сессия хранится вне репозитория с mode 0600 и атомарной заменой при ротации.
  Ошибки фонового сборщика публикуются фиксированными внутренними кодами и ограниченным
  диагностическим контекстом: HTTP-статус, операция, очищенные код/сообщение ФНС.
- Диагностика использует белый список скалярных полей; полные ответы, additionalInfo и состав
  покупок не журналируются. Из сообщений удаляются известные секреты сессии, ключ чека,
  email, телефоны, URL, длинные непрозрачные строки и вложенные объекты. Текст ограничен
  512 символами. Для внутренних исключений сохраняются тип и позиции кода без текста/locals.
  Эвристическая очистка не гарантирует удаления произвольных персональных сведений из прозы ФНС;
  история остаётся приватной. `/metrics` и MCP-диагностика защищены Bearer.
- Один сборщик, задержка ≥3.2 секунды между запросами, ограниченные retries и backoff.
  Повторная синхронизация не дублирует чеки, ошибки пагинации не считаются успехом.
- Контейнер non-root, rootfs read-only, capabilities удалены, no-new-privileges,
  лимиты CPU/RAM/PID, только loopback-публикация и существующая защищённая сеть.
- CI-ключ ограничен одной командой; персональные данные не нужны CI и не попадают в образ.

## Проверки

Unit/integration suite проверяет исходный CLI, изоляцию транспорта, токен refresh/rotation,
перезапуск расписания, повторные детали, SQL/CSV injection, ограничения ввода, расчёт возвратов,
настоящие MCP initialize/tools/list/tools/call, 401/403/421/413 и сохранность архива.
Дополнительно: неизвестный 422 и `authentication.failed`, живой прогресс, возобновление
после ошибок, восстановление истории после открытия базы, ограничение размера журнала,
редакция секретов, защищённость метрик, сбои SQLite и отсутствие busy loop планировщика.
Тесты запускаются без сети, только с синтетическими данными.

`pip-audit --strict --disable-pip -r requirements.txt` для закреплённых runtime-зависимостей
на дату проверки: **известных уязвимостей не найдено**. Это не аудит образа ОС;
результат зависит от актуальности базы advisory. CI повторяет dependency audit при каждом push.

## Остаточные риски и ограничения

- API ФНС неофициальный; refresh, формат полей и ограничения могут измениться.
  Полная проверка с реальным аккаунтом требует пользовательской сессии и сопоставления чека.
- SQLite/сессия защищены правами, но не зашифрованы на диске: root VPS находится в доверенной зоне.
  Резервные копии не создаются по решению владельца; потеря диска/VPS может привести к потере архива.
- Статический MCP bearer подходит для доверенной внутренней сети, не для публичного
  multi-user OAuth-сервиса. Любой авторизованный клиент видит весь личный архив.
- Владелец `main` может изменить deploy-код; контроль репозитория эквивалентен доверию
  к деплою на VPS. Ограниченный SSH-ключ не защищает от злонамеренного владельца репозитория.
- Данные чеков — недоверенный текст. MCP-инструкции предупреждают о prompt injection,
  но клиентская модель также должна трактовать чеки только как данные.
- SDK/базовый образ закреплены для воспроизводимости; обновлять их следует осознанно
  с повторением тестов и аудита. Закреплённый образ сам по себе не гарантирует актуальность ОС.
- Успех MCP healthcheck не означает актуальные чеки. Проверяйте last_success_at/last_error.
