# FNS Receipt Parser

## Наш fork: MCP-сервер и синхронизация каждые 4 часа

Этот fork сохраняет оригинальный CLI и добавляет приватный сервер **MCP Streamable HTTP**:

- `sync_status` — состояние, ошибки и время следующей синхронизации;
- `list_receipts` / `get_receipt` — поиск и состав сохранённых чеков;
- `spending_summary` — оплаченные суммы за вычетом возвратов, по продавцам;
- `sync_now` — внеочередной запуск без параллельных выгрузок.

Данные сохраняются в SQLite на VPS. Интервал — **14400 секунд** от начала предыдущего запуска;
срок следующего запуска переживает перезапуск. Если выгрузка занимает больше 4 часов,
следующая начинается через минуту после её окончания. Первый запуск — сразу.
Список чеков перечитывается целиком, детали уже сохранённых чеков не скачиваются повторно;
неудачные детали повторяются при следующей синхронизации. Это архив, не зеркало удалений ФНС.

Развёртывание — только через [GitHub Actions](.github/workflows/deploy.yml):
push в `main` → тесты в изолированном Docker + аудит зависимостей → ограниченный SSH-деплой
того же commit SHA → повторные тесты, healthcheck, MCP smoke-test и проверка сетевого выхода.
При ошибке проверки возвращается предыдущий образ. Pull request не разворачивается.
Подробности: [эксплуатация и подключение](deploy/README.md), [проверка безопасности](SECURITY_REVIEW.md).

Сервер: Python 3.12, зависимости закреплены версиями и хешами. В контейнере он работает
не от root, с read-only rootfs и обязательным Bearer-токеном MCP. Публичного порта нет.
Endpoint внутри сети `mcp_home`: `http://fns-receipts-mcp:8000/mcp`.

**Первый реальный сбор требует ручного входа в ФНС и установки сессии на VPS.**
Без неё сервер честно возвращает `authentication_required`, а не успешную пустую выгрузку.
Refresh token обновляется и сохраняется автоматически; при его истечении нужен повторный вход.
Секреты нельзя отправлять в чат, коммитить или добавлять в логи CI.

Для `spending_summary` сначала сравните сумму одного настоящего чека с кабинетом:
`amount_divisor=1` для рублей, `100` для копеек. Единицы не угадываются автоматически.
Возвраты вычитаются; учитываются только наличная и безналичная оплаты, чтобы не считать
авансы повторно. Чеки неизвестного формата исключаются с отдельным счётчиком.
Данные ФНС не являются полной историей всех расходов или банковских операций.

## Оригинальный CLI

Локальный Python-скрипт для экспорта ваших чеков из сервиса ФНС «Мои чеки онлайн» (`lkdr.nalog.ru`) в JSON и CSV.

Скрипт получает список чеков, загружает фискальные данные (состав) каждого чека и сохраняет результат в файлы, которые удобно открывать в Excel, LibreOffice или анализировать программно.

> Это независимый open-source проект. Он **не является** официальным продуктом ФНС России, не связан с ФНС России и не одобрен ею. Подробнее — в разделе [Disclaimer](#disclaimer).

## Возможности

- загрузка всего списка чеков или чеков за выбранный период (`--date-from`, `--date-to`);
- получение состава каждого чека (товарные позиции, НДС, суммы);
- полный экспорт в JSON;
- сводная CSV-таблица чеков и отдельная CSV-таблица товарных позиций;
- выбор каталога для результатов (`--output-dir`);
- повторные попытки при временных ошибках сервиса (HTTP 429/5xx, таймауты, сетевые сбои);
- ошибка по одному чеку не останавливает выгрузку остальных — такие чеки попадают в `errors.json`;
- Bearer token берётся из переменной окружения `FNS_TOKEN` или вводится скрыто в терминале и никогда не записывается в файлы.

## Требования

- Python 3.9 или новее (проверено на 3.9, 3.10, 3.12 и 3.14);
- доступ в интернет к `https://lkdr.nalog.ru`;
- учётная запись в «Мои чеки онлайн» и действующий Bearer token сессии.

Внешних зависимостей нет: используется только стандартная библиотека Python. `pip install` не нужен.

## Быстрый старт

```bash
python3 export_nalog_receipts.py
```

1. Скрипт попросит вставить Bearer token (ввод скрыт — символы не отображаются, это нормально).
2. Вставьте token и нажмите Enter.
3. Дождитесь сообщения «Готово.» — результаты будут в каталоге `nalog_receipts_export/`.

Справка по всем параметрам:

```bash
python3 export_nalog_receipts.py --help
```

## Получение Bearer token

Token — это **секрет**, равнозначный паролю: любой, у кого он есть, может просматривать ваши чеки, пока сессия активна. Не публикуйте его, не отправляйте в чаты и не коммитьте в Git.

Token выдаётся сервисом после входа в личный кабинет. Общий порядок получения через инструменты разработчика браузера:

1. Откройте <https://lkdr.nalog.ru> и войдите в свою учётную запись.
2. Откройте инструменты разработчика:
   - Chrome, Edge, Firefox — обычно `F12` или `Cmd+Option+I` (macOS) / `Ctrl+Shift+I` (Windows, Linux);
   - Safari — сначала включите возможности для разработчиков в настройках Safari (раздел «Дополнительно» / «Advanced»), затем откройте веб-инспектор.
3. Перейдите на вкладку сетевых запросов (обычно называется «Network» / «Сеть»).
4. Обновите страницу со списком чеков, чтобы запросы появились в списке.
5. Найдите запрос к адресу, оканчивающемуся на `/api/v1/receipt`, и откройте его заголовки запроса (Request Headers).
6. Найдите заголовок `Authorization` со значением вида `Bearer <длинная строка>`.
7. Скопируйте значение. Можно копировать как целиком (`Bearer ...`), так и только строку после `Bearer ` — скрипт понимает оба варианта.

Названия вкладок и расположение элементов отличаются в разных браузерах и их версиях — ориентируйтесь на смысл шагов.

Token действует ограниченное время. Если скрипт сообщает «Bearer token недействителен или истёк (HTTP 401)», обновите страницу личного кабинета (при необходимости войдите заново) и получите новый token.

### Передача token через переменную окружения

Вместо интерактивного ввода можно задать переменную `FNS_TOKEN`. Порядок такой: если `FNS_TOKEN` задана и не пуста — используется она, иначе token запрашивается скрыто в терминале.

```bash
read -rs FNS_TOKEN && export FNS_TOKEN   # ввод скрыт и не попадает в историю shell
python3 export_nalog_receipts.py
unset FNS_TOKEN
```

Не пишите token прямо в командной строке (`FNS_TOKEN=... python3 ...`): он сохранится в истории shell. Скрипт не читает файл `.env` автоматически; `.env.example` приведён только как образец имени переменной.

## Запуск без параметров

```bash
python3 export_nalog_receipts.py
```

Поведение совпадает с исходной версией v0.1: выгружаются все доступные чеки, результаты сохраняются в `./nalog_receipts_export/`, token запрашивается в терминале (если не задан `FNS_TOKEN`).

## Фильтрация по датам

```bash
python3 export_nalog_receipts.py \
  --date-from 2026-09-01 \
  --date-to 2026-09-17
```

- Формат дат — строго `YYYY-MM-DD`. Несуществующие даты (например, `2026-02-30`) отклоняются.
- Можно указать только одну границу: `--date-from` без `--date-to` и наоборот.
- Если `--date-from` позже `--date-to`, скрипт завершится с ошибкой (код 2) **до** запроса token и до обращения к API.
- Даты передаются в API в том же виде `YYYY-MM-DD`, без времени суток, — ровно так, как их отправляет веб-интерфейс `lkdr.nalog.ru` при выборе периода. Скрипт не добавляет время начала или конца суток; как именно сервис трактует границы периода, определяет сам сервис (ожидается, что так же, как при фильтрации в веб-интерфейсе).
- Если за период чеков нет, экспорт завершается успешно (код 0): создаются пустой `receipts_full.json` (`[]`) и CSV-файлы только с заголовками.

## Выбор каталога

```bash
python3 export_nalog_receipts.py --output-dir ~/Downloads/fns-receipts
python3 export_nalog_receipts.py --output-dir exports/2026-09
python3 export_nalog_receipts.py --output-dir /Users/me/Documents/receipts
```

- Каталог создаётся автоматически, включая промежуточные каталоги.
- Поддерживаются `~`, относительные (от текущего каталога) и абсолютные пути.
- Файлы с теми же именами в каталоге перезаписываются. Если при прошлом запуске в каталоге остался `errors.json`, а новый запуск прошёл без ошибок, старый `errors.json` удаляется, чтобы не вводить в заблуждение.

### Дополнительные параметры

| Параметр | По умолчанию | Описание |
|---|---|---|
| `--request-delay SECONDS` | `0.08` | Пауза между запросами к API (0–60 секунд). Увеличьте, если сервис отвечает HTTP 429. |

## Результаты

```text
nalog_receipts_export/
├── receipts_full.json     # полные данные: чек из списка + фискальные данные
├── receipts_summary.csv   # одна строка на чек
├── receipt_items.csv      # одна строка на товарную позицию
└── errors.json            # только если были ошибки по отдельным чекам
```

### `receipts_full.json`

Массив объектов вида:

```json
{
  "receipt": { "...": "данные чека из списка /v1/receipt" },
  "fiscal_data": { "...": "ответ /v1/receipt/fiscal_data или null" },
  "error": null
}
```

### `errors.json`

Создаётся только при наличии ошибок. Массив объектов `{"key": ..., "error": ...}`; для чеков без `key` дополнительно сохраняется исходный объект `receipt`.

### Ошибка «Сервис требует действия в личном кабинете (HTTP 422)»

Веб-интерфейс `lkdr.nalog.ru` получает HTTP 422 на запрос списка чеков, когда для учётной записи нужно выбрать настройки: в окне «Настройки отображения данных» по номеру телефона или email выбирается, показывать все чеки или только новые. Это не означает «чеков нет», поэтому скрипт завершается с кодом 1 и ничего не записывает. Откройте <https://lkdr.nalog.ru> в браузере, выберите вариант в этом окне (если оно появится) и запустите экспорт снова.

### Коды завершения

| Код | Значение |
|---|---|
| `0` | Экспорт завершён (возможно, с ошибками по отдельным чекам — см. `errors.json`) |
| `1` | Не удалось получить список чеков или записать результаты |
| `2` | Некорректные параметры, пустой token или невозможно создать каталог |
| `130` | Прервано пользователем (`Ctrl+C`) |

## Структура CSV

Оба CSV-файла сохраняются в кодировке **UTF-8 с BOM** и с разделителем **`;`** — так Excel корректно открывает кириллицу двойным щелчком.

Суммы (`totalSum`, `price`, `sum`, `ndsSum` и т. п.) сохраняются в том виде, в котором их возвращает сервис, без преобразования.

| Колонка | Описание |

| `createdDate` | Дата добавления чека в сервис |
| `receiveDate` | Дата получения чека сервисом |
| `receiptDateTime` | Дата и время чека из фискальных данных |
| `seller` | Продавец (из фискальных данных, иначе из списка) |
| `sellerInn` | ИНН продавца |
| `totalSum` | Итоговая сумма чека |
| `fiscalDocumentNumber` | Номер фискального документа (ФД) |
| `fiscalDriveNumber` | Номер фискального накопителя (ФН) |
| `sourceCode` | Источник поступления чека |
| `receiptState` | Состояние чека |
| `brandId` | Идентификатор бренда продавца |
| `itemsCount` | Количество позиций |

## Безопасность

- Token не сохраняется ни в JSON, ни в CSV, ни в `errors.json`, не выводится в терминал; если сервис вернёт token в тексте ошибки, он маскируется как `***`.
- Скрипт обращается только к `https://lkdr.nalog.ru`.
- Выгрузки содержат персональные данные (покупки, продавцы, суммы, фискальные реквизиты). Храните их в надёжном месте и не публикуйте.
- `.gitignore` исключает `.env`, каталоги `nalog_receipts_export*/` и `fns-receipts*/`, а также все `*.csv` и `*.json`. Если выбираете другой каталог для выгрузки, не размещайте его внутри репозитория или проверяйте `git status` перед коммитом.
- Никогда не публикуйте token, cookies сессии, реальные выгрузки и скриншоты с персональными данными — в том числе в issue и Pull Request.

## Ограничения

- Используются интерфейсы веб-приложения `lkdr.nalog.ru`, которые не документированы публично и могут измениться без предупреждения.
- Token имеет ограниченный срок действия; при длительной выгрузке он может истечь — тогда часть чеков попадёт в `errors.json` с ошибкой HTTP 401.
- Повторные попытки ограничены: не более 3 попыток на запрос с паузами 1 и 2 секунды (при HTTP 429 учитывается заголовок `Retry-After`, но не более 30 секунд).
- Любая ошибка при получении списка чеков, включая HTTP 422, останавливает экспорт (код 1) — частичный список не сохраняется как успешный. Веб-интерфейс, в отличие от скрипта, скрывает большинство таких ошибок и показывает пустой список.
- Список запрашивается страницами по 10 чеков, как в веб-интерфейсе; параметра для изменения размера страницы нет, поскольку другие значения не проверены на реальном сервисе. Получение списка заканчивается на неполной странице или при `hasMore: false` в ответе.
- Если сервис возвращает страницу без новых чеков (например, игнорирует `offset`), получение списка останавливается с предупреждением, чтобы не зациклиться.
- Выгрузка не инкрементальная: каждый запуск заново загружает все чеки за выбранный период.

## Тесты

Тесты используют только `unittest` и `unittest.mock`, не обращаются к сервису ФНС и не требуют token:

```bash
python3 -m py_compile export_nalog_receipts.py
python3 -m unittest discover -v
```

Те же проверки выполняются в GitHub Actions (`.github/workflows/tests.yml`) при push и Pull Request.

## Разработка

- Весь код — один файл `export_nalog_receipts.py` без зависимостей; тесты — в `tests/`.
- Изменения вносятся через отдельные ветки и Pull Request. Исходная проверенная версия помечена тегом `v0.1.0-working`.
- В тестах используйте только синтетические данные: никаких реальных чеков, ИНН, имён и token.
- Изменения формата запросов к API требуют ручной проверки с реальной учётной записью.
